# CinoCode Phase 1 Boundary Map

## Scope

This map identifies current UI/AI execution mixing without changing production routing. Target responsibilities come from the approved working baseline; physical platform architecture remains undecided.

| Current responsibility | Target responsibility | Migration strategy | Risk | Affected files |
|---|---|---|---|---|
| `sendMessage` owns UI locking, intent, prompt assembly, model routing, network execution, stream reading, persistence, TTS, and rendering | Client chat controller retains UI/persistence; platform execution boundary owns managed AI execution | Characterize each stage, introduce `PlatformClient` behind legacy payload adapter, route only approved managed chat calls | Critical: behavior drift or duplicate persistence | `assets/js/main.js:7650`, `src/adapters/platform-client.js` |
| Browser parses provider/model labels and creates fallback queues | Provider registry/orchestrator owns managed capabilities and fallback; client retains explicit local integration policy | Freeze current orders, build registry metadata, compare selected/fallback provider in tests | High: changed provider order, cost, or capability | `assets/js/main.js:8175`, `netlify/functions/ai-chat.js:95`, `netlify/functions/ai-chat.js:438` |
| Browser stores direct-provider keys and calls provider endpoints | Managed credentials and calls remain server/platform-side | Inventory/deprecate only after approved user-key ADR; do not delete in Phase 2 | Critical: secret exposure or user workflow loss | `assets/js/main.js:2701`, `assets/js/main.js:8193`, `assets/js/main.js:8430` |
| Prompt rules are assembled inside chat/UI flow | Prompt engine owns versioned prompt composition; client supplies explicit context | Extract pure prompt inputs/outputs with snapshots before changing call sites | Critical: persona, safety, or answer-style drift | `assets/js/main.js:8076` through request assembly, `src/adapters/prompt-engine.js` |
| Direct-provider stream parsing updates DOM and triggers TTS per sentence | Stream adapter normalizes events; client renderer/TTS consumes normalized deltas | Execute current parser in tests, define stream contract via required ADR, then insert adapter | Critical: duplicated/lost text or broken cancellation | `assets/js/main.js:8844`, `assets/js/main.js:8874`, `src/adapters/stream-adapter.js` |
| Stop button directly aborts current controller and edits DOM | Client cancellation controller remains responsible for UI; platform stream must accept cancellation | Preserve `stopGeneration`; later bind controller to platform transport without changing button semantics | High: orphaned upstream work or stuck UI | `assets/js/main.js:7127`, `assets/js/main.js:7138` |
| Access-token/guest-token acquisition is coupled to fetch retry | Platform client transport adds current headers; auth module remains identity owner | Wrap `protectedApiFetch` behavior without changing headers or one-time guest retry | High: repeated Turnstile or unauthorized provider calls | `assets/js/main.js:168`, `assets/js/main.js:210`, `assets/js/auth-core.js:167` |
| Workspace load/save and metadata normalization are coordinated inside UI script | Storage adapter describes local persistence boundary; existing storage remains authoritative | Characterize localStorage-to-IDB migration, introduce adapter only after migration tests | High: conversation loss or duplicate workspace | `assets/js/main.js:437`, `assets/js/main.js:3394`, `assets/js/main.js:3400`, `src/adapters/storage-adapter.js` |
| Image flow chooses direct Runware or server chain and writes DOM/artifacts | Platform image execution owns managed providers; client keeps prompt UX/render/artifact storage | Freeze `ImageRequest`/`ImageResponse`, retain direct path pending ADR, later route managed calls via client adapter | High: image regressions, quota duplication, lost diagnostics | `assets/js/main.js:1217`, `assets/js/main.js:1312`, `netlify/functions/generate-image.js:532` |
| Vision capability is inferred in client and again resolved server-side | Capability registry owns managed model capabilities; client retains attachment capture | Freeze current vision allowlists and attachment limit, expose approved capability metadata later | High: image sent to text-only provider | `assets/js/main.js:2999`, `assets/js/main.js:8244`, `netlify/functions/ai-chat.js:46` |
| Web search is triggered in chat flow and injected into prompt context | Search remains dedicated server operation; prompt engine consumes explicit search context | Keep endpoint and result shapes, isolate prompt injection after prompt snapshots exist | Medium: unsupported claims or context-order drift | `assets/js/main.js:6261`, `assets/js/main.js:8163`, `netlify/functions/web-search.js:51` |
| Browser video workflow uses AI-generated scene images plus Canvas/MediaRecorder | Browser-only artifact workflow remains client-owned | Do not route to AI Engine until a separate approved video API exists | Medium: falsely labeling storyboard as generative video | `assets/js/main.js:4642`, `assets/js/main.js:4702`, `assets/js/main.js:4955` |
| TTS selection, fallback, UI, and playback share one global script | Client voice adapter remains browser-owned; optional TTS endpoint remains external adapter | Characterize existing route/voice behavior before any extraction | Medium: voice mismatch or playback lock | `assets/js/tts-core.js:759`, `assets/js/tts-core.js:950`, `server.py` |
| Document parsing and chunk choice occur in browser and feed chat prompt construction | Browser document adapter owns parsing; platform contract receives bounded text/attachments | Preserve format/size/timeout guards; separate only request mapping | High: oversized requests or lost document context | `assets/js/modules/documents.js`, `assets/js/main.js:7802` |
| Netlify functions and Vercel adapters expose overlapping routes | Deployment adapter remains compatibility-only until runtime authority is approved | Add parity tests; consolidate only after deployment ADR | Medium: route divergence | `netlify.toml`, `vercel.json`, `api/_netlify-adapter.js`, `netlify/functions/*` |

## Phase 1 Boundary Enforcement

- `src/adapters/*` is not imported by `cinocode_chat.html`, `assets/js/*`, or `netlify/functions/*`.
- Every skeleton method throws `adapter_not_configured`.
- `tests/phase1-contracts.test.js` fails if a production entry point begins using the skeletons.
- Production routing therefore remains unchanged.
